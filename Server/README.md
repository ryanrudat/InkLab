# InkLab proxy (backend)

Part of the public **InkLab** repo: <https://github.com/ryanrudat/InkLab> (this is `Server/`; the iPad app and the 13 Swift engine packages live alongside it).

The server-side boundary for **all** Anthropic calls (ADR 0002 / [ADR 0003](../docs/decisions/0003-ipados-floor-and-backend-proxy.md)).
The iPad never calls Anthropic directly — it calls this proxy, which holds the API key, enforces the
consent/age gate, applies moderation, and keeps zero-data-retention posture. TypeScript runs directly
on Node 24.12+ (stable native type-stripping — no build step), with a separate strict `tsc` check.
Model id `claude-opus-4-8`.

> **Scope: this proxy is STATELESS and stays that way.** It forwards prompts to Claude and stores
> **nothing** — no notebooks, no ink, no user content. Backup/sync is deliberately **serverless**
> (Files/iCloud-Drive export, then CloudKit — the user's own iCloud); see
> [ADR 0006](../docs/decisions/0006-backup-and-sync.md). Putting notebook storage here would make us a
> custodian of minors' handwriting (COPPA/FERPA) and break the on-device privacy posture — so don't.

## Run

Node 24.18.0 is pinned in `.nvmrc` and CI; the supported runtime range starts at 24.12.0, where native
TypeScript type stripping became stable. The API key lives only in `Server/.env` (gitignored).
Create it from the tracked, secret-free template; `npm start` auto-loads it via
`node --env-file-if-exists=.env`.

```sh
cd Server
nvm use
npm ci                                     # exact tools from package-lock.json
cp .env.example .env                       # then add ANTHROPIC_API_KEY
npm run check                              # strict type-check + 42 offline tests
npm start                                  # loads ANTHROPIC_API_KEY from .env; proxy on :8787
```

> **Live (2026-06-07):** the app now calls this proxy for real. Both `/make-real` (generative
> widgets) and `/recognize` (Claude-vision handwriting recognition) are wired and verified
> end-to-end against `claude-opus-4-8`.

## Deploy (Railway — interim)

On a real iPad the app can't reach the Mac's `localhost`, so the proxy must run on an always-on,
internet-reachable host. **Interim host: Railway** (chosen 2026-06-07 because it's already paid for).
⚠️ This is **not** a final production decision — hosting/placement must be revisited **before
publication**: region / data residency for minors, negotiated ZDR, moderation, auth + rate limiting,
and cost. See [ADR 0003](../docs/decisions/0003-ipados-floor-and-backend-proxy.md) and `PROGRESS.md`.

```sh
railway login                                        # one-time, opens a browser
cd Server
railway init                                         # create/link a Railway project + service
railway variables --set ANTHROPIC_API_KEY=sk-ant-... # key lives on the server, NEVER in the app
railway up                                            # Railpack build (Node 24 via .nvmrc) + deploy
railway domain                                        # generate the public HTTPS URL
```

`railway.json` selects Railpack, pins the start command, and verifies `GET /health` before a deployment
becomes active. `.nvmrc` pins Node 24.18.0. Railway injects `PORT` (the server already reads it); no
`.env` is uploaded (gitignored + `.railwayignore`). After deploy, create the app's ignored
`InkLab/Info.local.plist` + `InkLab/Secrets.xcconfig` overrides as described in the root README, then
set **`MakeRealBaseURL`** to the `railway domain` URL.

### Auth (shared secret)
`/make-real` and `/recognize` require `Authorization: Bearer $INKLAB_PROXY_SECRET` whenever
`INKLAB_PROXY_SECRET` is set (Railway variable + local `.env`); unset = open (local dev / tests).
`/health` is always open. The app sends it from `Info.plist` `MakeRealProxySecret` (same value).
⚠️ **Obfuscation-grade, not real auth** — a secret embedded in a distributed app can be extracted; this
stops casual abuse of the public URL, not a determined attacker. Real per-user auth (tokens / App
Attest) + rate limiting are still pre-ship items.

## Endpoints
- `POST /recognize` — `{ session, rasterPngBase64, strokes, domain, context }` → a **validated**
  `RecognitionResult` (the cloud fallback for the swappable recognizer). Correct-or-silent: anything
  that doesn't parse to valid structure comes back as `unrecognized`, never a guess.
- `POST /make-real` — `{ session, prompt }` → a self-contained widget `{ html, layout, complete, passes }`,
  generated by `claude-opus-4-8` with `max_tokens: 8192` (high enough that most widgets finish in **one
  pass**), assembled by the **multi-pass assembler** (continues past truncation, stitches) and rejected
  (422) if it isn't sandbox-safe. Orchestration + the system prompt live in `src/makeReal.ts`. Only the
  HTML document is returned (`extractWidgetHtml` drops preamble, ```` ``` ```` fences and closing remarks),
  and `layout` (`portrait` 360×540 · `landscape` 560×360 · `square` 440×440) is read from the widget's
  `<meta name="inklab-layout">`, which the prompt asks the model to declare. Errors: `400` empty / too-long
  prompt, `403` consent, `422` `declined` (a refusal — not retried) or `unsafe widget`, `502` `incomplete
  generation` / `no widget` / `upstream error`, `504` `generation timed out` (whole-request deadline,
  170s by default, `MAKE_REAL_DEADLINE_MS`; the app waits 185s). The system prompt also instructs widgets with a primary
  text/expression input (graphers, calculators) to expose `window.inklab.setInput(text)` — the **widget
  input protocol** the app uses for handwrite-to-plot (fill the main input *and* trigger the
  plot/compute routine).
- `GET /health` → `{ ok: true }`.

## The tested core (`src/`)
- `consent.ts` — `cloudEligible(session)`; mirrors the Swift `DefaultCloudPolicy`. The server enforces
  it independently (defence-in-depth for minors' data — it never calls Anthropic for an ineligible
  session). **Fail-closed:** it validates the session *shape* at runtime and whitelists only known-eligible
  kinds (adult / minorConsented / schoolManaged, with `ageVerified`), defaulting to BLOCKED — so a typo'd,
  tampered, missing, or unknown `userKind` can no longer fall through to allowed.
- `assembler.ts` — the make-real multi-pass assembler (`DONE_MARKER`; feed-partial-back-and-stitch).
- `validate.ts` — `validateRecognition` (correct-or-silent) and `validateWidgetHtml` (rejects external
  scripts/stylesheets, `fetch`/`XMLHttpRequest`, and `<iframe>`, so it runs in a locked-down WKWebView).
  The tripwire was broadened (now also `img` / `<meta refresh>` / `<base>` / `sendBeacon` / WebSocket /
  EventSource / dynamic `import()` / css `url()` / protocol-relative `//`) — still **defense-in-depth**; the
  on-device WKWebView CSP is the real boundary.
- `recognize.ts` — orchestration (gate → prompt → call → validate).
- `anthropic.ts` — the real HTTP client behind the `AnthropicClient` interface (mocked in tests).

## Hardening (2026-06-09)
- **Consent gate is now fail-closed.** `consent.ts` `cloudEligible` validates the session shape at runtime and
  whitelists only known-eligible kinds (adult / minorConsented / schoolManaged, with `ageVerified`), defaulting
  to BLOCKED. Previously it only blocked the literal `userKind === 'minorUnconsented'`, so any typo'd / tampered
  / missing / unknown `userKind` fell through to allowed — a minor's ink could reach Anthropic. New tests.
- **No internals leaked.** Error responses are now generic (`500` "internal error" / `502` "upstream error");
  `anthropic.ts` no longer embeds the verbatim upstream Anthropic error body (incl. `request_id`) in the
  propagated error.
- **Request hardening.** An 8 MB request body-size cap (`413` on exceed), and malformed/missing JSON now returns
  `400` (was a `500`).
- **`validateWidgetHtml` tripwire broadened** (now also `img` / `<meta refresh>` / `<base>` / `sendBeacon` /
  WebSocket / EventSource / dynamic `import()` / css `url()` / protocol-relative `//`) — still defense-in-depth;
  the on-device WKWebView CSP is the real boundary. `stripMarker` now removes only the **trailing** DONE marker
  (not every occurrence).
- **Tests:** 23 (was 19).

## Deferred / Status (2026-06-08)
- **make-real:** model `claude-opus-4-8` @ `max_tokens 8192` (one-pass; no truncation round-trips for
  most widgets). The system prompt now asks input-driven widgets to expose `window.inklab.setInput(text)`
  for the app's handwrite-to-plot flow.
- Real input/output **moderation** (Organizations-Serving-Minors safeguard) — currently an interface.
- **Auth:** shared-secret Bearer gate is in (see *Auth* above) — obfuscation-grade; real per-user auth
  (tokens / App Attest) + **rate limiting** still needed. **Deploy:** live on Railway (interim);
  final hosting/placement is an open **pre-publication decision** (data residency, ZDR, cost).
- Negotiated **ZDR** wiring + a written data-retention policy; data minimization (crop/strip).
- Verifiable parental-consent verification. See
  [docs/compliance-checklist.md](../docs/compliance-checklist.md).
- **Note:** `validateWidgetHtml` (blocks external scripts/stylesheets, network, `<iframe>`) is
  defense-in-depth only — the real security boundary is **network isolation** in the on-device,
  locked-down WKWebView (CSP `default-src 'none'`, `baseURL` nil, navigation cancelled, non-persistent
  store). That app-side CSP now also allows `script-src 'unsafe-eval'` so graphers/calculators can
  evaluate a user-typed expression; this is safe precisely because the network boundary holds — and it
  lives in the app (`WebWidgetView`), **not** in this server's validator.
